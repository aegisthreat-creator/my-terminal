Guidelines, Tutorials & Tools
Learn how to use the real execution terminal safely and effectively.

🚀 Quick start

  1. Choose a language from the Language menu.
  2. Choose an available real compiler/runtime.
  3. Write or paste your source code.
  4. Add stdin if your program expects input.
  5. Press Run or Ctrl+Enter.
  6. Read the actual compiler/program output in the terminal.

📚 Tutorial 1 — First program

Select Python, then run:

name = input("Name: ")
print("Hello,", name)

Put your name in the stdin box, then run it. The result comes from the real Python runtime.

🧪 Tutorial 2 — Compilation errors

Try deliberately making a syntax error. The terminal will show the real compiler/runtime error.

Fix the source and run it again. This is useful for learning debugging instead of receiving pre-written fake output.

⌨️ Terminal commands

help
run
clear
lang
compiler

Type commands into the command bar at the bottom of the terminal.

🔧 Options & input

  • stdin: data supplied to your program.
  • Compiler options: options passed to the compiler when supported.
  • Runtime arguments: arguments supplied when supported.
  • Not every language/runtime accepts every option.

🛡️ Safety & limitations

Execution is sandboxed by the remote service. The page does not pretend that every catalog entry has a compiler.

A language can appear in the catalog while showing no live runtime available. In that case the terminal refuses to simulate execution.

🌐 How the real system works

Browser editor → HTTPS request → real compiler/runtime → sandboxed execution → stdout/stderr → terminal.

The large language catalog is local data in this page; the live compiler list is fetched separately from the execution service.

⏱️ Loading time

The 693-name catalog does not need minutes to load. It is embedded in the HTML, so the browser can populate it immediately after the page loads.

The live compiler/runtime list requires an internet request. On a normal connection this is usually well under a minute, often only a few seconds. A slow connection or unavailable service can take longer.

Important: there is no fixed number of minutes I can guarantee because network speed and the remote service determine the live-list response time.

🐞 Troubleshooting

  • Catalog appears but compiler says unavailable: that language is listed, but the live service did not report a matching runtime.
  • Run fails: inspect compiler/program output and fix the source.
  • Nothing loads: check your internet connection and reload Chrome.
  • Input program waits: provide the required data in the stdin box.

🧭 Guidelines & best practices

  • Start with a small program to verify the selected runtime.
  • Use compiler options only when you know the compiler accepts them.
  • Use stdin for input instead of hard-coding test data.
  • Check compiler errors before changing your program.
  • Never put passwords, API keys, or private information in code.
  • Remote execution depends on internet/service availability.

IMPORTANT A catalog entry does not guarantee a live runtime.

⚙️ Important system information

  • 693 language names are listed in the catalog.
  • The live compiler list is checked when the page starts.
  • Chart 1 counts actual runs made from this page.
  • Unsupported languages are never given fake output.
  • Chrome cannot directly become a native OS shell from a normal webpage.
  • Execution is performed by a real remote sandbox service.
